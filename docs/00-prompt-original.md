# 00-原始需求（首个提示词原文·冻结）

> **地位**：本文是整份交付的唯一需求基线。任何文档、代码、验收口径与本文件冲突时，**以本文件为准**。
> **来源**：用户首个提示词截图（`clipboard_1794398176787_0iepzl.png`），2026-11-11 逐字转录，仅统一标点、不改语义、不删条目。

## 第一段：交付约束

请在工作区创建项目目录「新建文件夹(7)」，仅实现后端，不生成任何前端代码，前端后续由我提供；后端需包含登录、注册与新手教程功能，交付时仅给完整、可直接使用、能力边界清晰的 backend 实现成品，不附额外教程或原理讲解。

## 第二段：系统定位

请构建面向个人工作、学习与日常场景的个人超级 agents 系统，以"尽可能全能、样样精通"为设计目标，覆盖编程开发、文档写作、信息整理、任务规划、创意构思与沟通协作等多类任务；系统由统一超级 agents 层和多个子 agents 组成，子 agents 具备垂直行业知识、专业知识文档、专业 skill、角色编排与共享记忆，统一接入 API、MCP、skill 市场知识库、浏览器沙箱等能力。

## 第三段：成品按六部分组织

1. **总体定位**：说明目标与组成；
2. **能力清单**：列出任务覆盖与内置机制；
3. **分工协作**：定义职责、编排、按任务模型调度、按任务 agents 调配与权力分配；
4. **交互规范**：明确统一交互风格、对话共享记忆与上下文策略；
5. **边界处理**：定义信息不足、超出能力范围、越权、幻觉、合规、循环报错与安全降级的处理策略；
6. **验收标准**：给出正确性、可观测性、可控性、成本与自净化的验收口径。

## 第四段：能力清单必须逐项标注五要素

能力清单需对以下逐项按 **触发条件、负责 agents、权限边界、可观测信号、降级/终止条件** 标注：

> 自动化、懒加载、全可视化、权力分配、安全、错误纠错、自净化、正确性校验、合规检查、对话共享记忆、全链路监控、按任务模型调度、工具调用、流程编排、循环报错处理、数据飞轮、评估驱动检查与工具增强（即 RAG）、可观测与告警、安全与治理、组织与组合管理、成本与算力优化、上下文优化、按任务 agents 调配、防幻觉、沙箱

（原文 25 条；其中"评估驱动检查与工具增强（即 RAG）"在实现中被拆为 C17 / C18 两项独立机制，故 `docs/02` 共 26 条，属细化而非扩充，映射见 02 文件"覆盖度自查"。）

## 第五段：整体目标

整体需满足多 agent 协作的 **全自动化、安全化、正确化、全可视化、可控化、全面化、自进化与规划**，确保 **可直接运行、可观测、可控且不越权**。

## 第六段：执行方式

先制作项目计划再执行（使用 rust 编程语言构建）。
