# 86 · 垂直 agent 的准入、增补与裁撤

> 一句话：**"多造几个智能体"不是复制粘贴改名，而是四道准入加十三处同步。**
> 本文是 2026-11-14 这轮扩容（9 → 12）的判据留痕，也是以后想加/想删时的操作手册。
> 没有判据的扩容会让花名册变成一个"什么都能沾一点、什么都不精"的列表——那比少几个 agent 更糟。

- 当前花名册：**12 个**（1 总控 + 6 通用职能 + 4 垂直域 + 1 审核）
- 注册表：`src/domain/agent.rs` 的 `AGENTS`（唯一真源）
- 名册文档：`docs/03-division-of-labor.md`（由 `scripts/gen-spec-docs.py` 生成，**禁止手改**）

---

## 1. 四道准入：什么才配单独成一个 agent

四条**全部满足**才立册；只满足两条以内的，一律归并到既有 agent 的 `task_types` / `keywords` 里。

| # | 准入条件 | 问法 | 不合格的典型样子 |
| --- | --- | --- | --- |
| A1 | **任务类型组合不与他人重合** | 它的 `task_types` 组合是不是某个既有 agent 的子集？ | 只有 `Writing`，和 `doc-agent` 完全一样 |
| A2 | **有可评审的独立产出物** | 它交付的东西能不能被别人打勾打叉？ | 只输出"建议""思路"，没有可核对清单 |
| A3 | **有独立的对错判据** | 同一件事，它做对和做错能不能分开？ | 产出全靠感觉，好坏无法裁决 |
| A4 | **有独立知识库实体** | `docs/kb/` 下有没有一份属于它的？ | 借用别人的 `writing-style.md` 就算完 |

> A2/A3 是这套标准里最容易被跳过、也最值钱的两条。一个 agent 如果没有"能被评审的产物"，
> 它在编排图里就只是个更长的提示词——占预算、增延迟、不给确定性。

## 2. 本轮新增的四个垂直域

四个都是按 A1~A4 逐条对过的，`task_types` 组合**互不相同**，也不与既有通用 agent 重合。

| agent | 域 | 职责（summary 原文口径） | 任务类型 | 关键词（节选） | 知识库 |
| --- | --- | --- | --- | --- | --- |
| `game-agent` | 游戏设计 | 玩法核心循环、数值曲线与通胀控制、关卡节奏、系统奖励结构；产出**可评审的设计检查表** | Ideation + Planning | 玩法、关卡、数值、战斗、平衡、掉落、肉鸽、策划 | `docs/kb/game-design-checklist.md` |
| `finance-agent` | 财务核算 | 费用口径（期间/主体/含税）、单据链五单一致、预算与成本归集、异常付款信号；**只给可核对清单，不猜金额** | Writing + Planning | 报销、发票、对账、预算、成本、税务、现金流 | `docs/kb/finance-checklist.md` |
| `legal-agent` | 法务合同 | 合同条款体检、必备条款缺失与高危句式、风险分级与谈判底线；**不出法律意见，重大条款交律师复核** | Writing + Research | 合同、条款、违约、保密、知识产权、管辖、甲方乙方 | `docs/kb/contract-checklist.md` |
| `data-agent` | 数据分析 | 指标定义三要素、异常波动归因、报表口径统一、数据质量六查；**口径未确认前不下结论** | Research + Coding | 指标、口径、报表、同比、环比、转化率、留存、埋点 | `docs/kb/metrics-handbook.md` |

三个刻意写进职责里的"不做"值得单独点出来，它们就是 A3 的落地方式：

- `finance-agent` —— **不猜金额**。缺单据就报缺单据，不许用"大约""预计"凑一个数。
- `legal-agent` —— **不出法律意见**。给条款风险分级和谈判底线，重大条款明确写"交律师复核"。
- `data-agent` —— **口径未确认前不下结论**。宁可回一句"口径待确认"，也不给一个看着漂亮但口径漂移的数字。

> 这三个"不做"是本轮的创意点：垂直 agent 的价值不在"知道得更多"，而在**知道什么时候必须停下**。
> 通用 agent 敢猜，垂直 agent 不敢猜——这才是老板愿意把报销和合同交给它的理由。

## 3. 本轮裁撤：`collab-agent` 为什么被归并

`collab-agent`（协作对齐）撤册，职责并入 `doc-agent` 的 `Collaboration` 任务类型（关键词补"分工/催办/沟通/对齐"）。

| 准入项 | 判定 | 依据 |
| --- | --- | --- |
| A1 任务类型 | **不合格** | 与 `doc-agent` 同为"写作+协作"同一组，属子集 |
| A2 独立产出物 | **不合格** | 交付物就是纪要/分工表，与 `doc-agent` 的会议纪要同形 |
| A3 独立判据 | **不合格** | 对错判据与写作类一致（完整性、术语一致） |
| A4 独立知识库 | **不合格** | 无专属 kb 文件，靠 `writing-style.md` |

四条全不合格 → 归并。同步动作：删 `workers/collab-agent.py`、从 `AGENTS` 移除、
`docs/03` 的 `collab` 残留清零、长跑用例里的 collab 目标替换。

> 顺带一个判断依据留在这里：**"合并后路由还会不会投错"是可验证的**——
> `collaboration_still_has_owner` 这条测试就是为它写的：撤了 agent，但 `Collaboration`
> 任务类型必须仍有 agent 承接，否则协作类请求会掉进兜底。

## 4. 新增一个 agent 的十三处同步（漏一处都会留坑）

实测扫描（按 agent id 在仓库里的硬编码点统计）：

| # | 位置 | 改什么 | 漏改的后果 |
| --- | --- | --- | --- |
| 1 | `src/domain/agent.rs` | `AGENTS` 加块：id/name/domain/summary/task_types/keywords/vk/doc_refs/权限/沙箱/模型档 | 调不到该 agent |
| 2 | `workers/<id>.py` | 一个 worker 脚本，**复用** `workers/_common.py` 的切词与骨架；主题取词必须走 `TG.pick(g, kw, fallback, domain="<域>")` | 运行期找不到执行体；或产出标题是半句话（见 §7） |
| 3 | `docs/kb/<topic>.md` | 独立知识库文件，`doc_refs` 指过去 | `doc_refs_point_to_existing_files` 直接红 |
| 4 | `src/orchestration/routing.rs` | 仅在需要硬规则时加分支（现 9/12 有硬规则） | 泛化路由能兜，但特定说法会被误投 |
| 5 | `src/domain/capability.rs` | 只有新增"能力项"时才改（纯加 agent 不动它） | 声明与实现漂移 |
| 6 | `scripts/matrix.py` | 换件矩阵覆盖新 agent | 新 agent 的沙箱/权限没被真验过 |
| 7 | `scripts/verify_runner.py` | 让新 worker 真跑一遍 | 只注册没跑过 = 纸面 agent |
| 8 | `scripts/probe_llm_soak.py` | 若走模型，加进用例目标池 | 长跑覆盖不到它，退化无人知 |
| 9 | `scripts/smoke.py` | 对外可见行为的断言 | 契约变了没人管 |
| 10 | `docs/02`、`docs/03` | 跑 `python scripts/gen-spec-docs.py` 重生成，**不许手改** | `--check` 打回 |
| 11 | 全仓"N 个 agent"口径 | `docs/01`、`docs/10`、`docs/40`、`docs/README.md` | 数字漂移（本轮修了 5 处：10/9 → 12） |
| 12 | `scripts/regress_all.py` | 24 道全绿 | 无证据 = 没做完 |
| 13 | `workers/_topic_guard.py` | `DOMAINS` 里登记该域的**对象词表**（只放对象，不放视角词） | 该域取词只能退回分词结果，会吐 `段剧情` / `上线` 这类碎片 |

> 第 10 条特别说明：`docs/02`、`docs/03` 是从源码生成的。手改一次，下次生成就冲掉，
> 而 `--check` 会把这种"看起来对了"的状态判成不一致 —— 它守的正是"文档不许比源码跑得快"。

## 5. 已有守护（`cargo test`，174 项里的 6 条）

这些测试的作用不是"跑通"，而是**锁住判据**——以后有人违规扩缩容，它们会红。

| 测试 | 守什么 | 违规时的样子 |
| --- | --- | --- |
| `registry_is_consistent` | 注册表内部自洽（无重复 id、字段齐备） | 复制粘贴改名漏改 id |
| `no_hollow_agent` | 禁止空壳 agent（无 task_types、无 keywords） | 为了凑数加个"AI Agent" |
| `collaboration_still_has_owner` | 撤并后任务类型仍有归属 | 撤 agent 把一类请求撤成孤儿 |
| `vertical_goals_to_vertical_agents`（路由层） | 垂直域目标必须投垂直 agent | 合同请求被打到 `doc-agent` |
| `keywords_are_unique_within_task_type` | 同一任务类型内关键词不许撞车 | 两个 agent 抢一句话，胜负由表序决定 |
| `doc_refs_point_to_existing_files` | `doc_refs` 必须指向真实文件 | 13 处引用一度全是空引用 |

> 最后两条是本轮新增。`doc_refs` 那条的起因很具体：曾出现 `doc_refs` 里 13 个路径**全部不存在**，
> 而当时所有测试都是绿的——因为没人检查"引用的文件是否真存在"。这类"引用为空但没人报错"
> 的问题，只有靠测试才能长期挡住。

## 7. 垂直 worker 的取词守卫（门禁 20）

垂直 agent 的产出全部挂在 `topic` 上：它是每条输出的主语（"《万炉》按…口径体检"、
"这批接口的验收…"）。topic 取错，后面每一条检查项都在对着错的对象做，而**格式全都合法**——
这是最难被肉眼发现的一类退化。

### 7.1 三类真实缺陷，都是实跑抓出来的

| 输入 | 旧产出 | 病 |
| --- | --- | --- |
| `帮我理一下万炉第三章的伏笔，反派动机是不是站得住` | `理一下万炉第三章的伏笔` | 半句：带着引导动词，长度也没超 |
| `这段剧情的主线推进太慢，人物动机也说不通` | `段剧情` / `这段剧情的主线推进太慢` | 分词碎片的量词残留 / 整句回显 |
| `上线前跑一遍冒烟，缺陷按级别分一下` | `上线` | 动词短语被当成对象（两字，长度判据拦不住） |
| `对标两款竞品做个市场分析` | `分析` / `建议` | 视角词顶替对象 |
| `世界观设定跟旧设定冲突了` | 兜底串 | 分词给出**空表**，无词可用 |

### 7.2 修法：把域知识变成声明，而不是从分词里猜

`_topic_guard.DOMAINS` 存三张**对象词表**（narrative / market / qa），worker 与门禁共用同一份。
为什么不直接用 `_common.keywords()`：那是分词产物，**推断式、会抖**；域词表是**声明式、稳定**。
取词顺序由此变成：

```
书名号专名 → 章节号主体 → 公共主题（须过句法判据） → 域对象词表 → 分词关键词 → 兜底串
```

判定"能不能当主题"的判据有七条，全部有来历：串内带标点 / 指示量词开头 / 超长且含虚词 /
补语或动量字收尾（`改完`、`校一遍`）/ 含疑问词（`选哪个渠道`）/ 连词开头（`再给个定价建议`）/
两字且趋向字收尾（`上线`）。最后两条是第三轮才补上的——前两轮跑完还剩 `列验收标准`、
`上线` 这样的产出。

### 7.3 这道门禁自己假绿过一轮（务必记住）

第一版探针**自己写了一份域词表**喂给 `pick()`，12/12 全绿。但把同一批目标交给真实 worker，
产出是 `段剧情`、`上线`、兜底串——因为 worker 传的是 `_common.keywords()`，跟手写词表
根本不是一回事。**门禁的输入必须与线上调用逐字同源**，否则绿的是探针自己。

现在两条同源约束写在探针文件头：
- 关键词：`_common.keywords(goal, 8)`
- 域词表：`_topic_guard.DOMAINS`

改这道门禁时，先确认这两条没被改回"探针自带一份词表"。

### 7.4 它会红吗

`--drill-no-guard`：把取词换回裸 `_common.topic()`，同一批 12 例必须出现红。
实测 **10/12 变红**，探针据此自证有判定力；已作为第 2 项负向演练挂进 `regress_all.py --with-drills`。
