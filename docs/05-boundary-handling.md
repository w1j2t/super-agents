# 05 边界处理

> 六部分之一（**边界处理**）。回答一个问题：**什么时候这个系统会拒绝、会降级、会中止，以及中止得干不干净。**
> 原则：边界要写在代码里，不能写在文档里靠自觉；且**不提供关闭开关**——能关的安全等于没有。

## 0. 原文七类边界 → 本文落点

首个需求列了会被问到的七类边界：**信息不足、超出能力、幻觉、合规、循环报错、安全降级、交互风格**。
每条都必须有明确处置口径——含糊回答等于没有边界。

| # | 原文边界 | 系统处置 | 本文落点 | 代码位置 |
| --- | --- | --- | --- | --- |
| 1 | 信息不足 | 不猜：回问或降低置信度并说明缺什么；装配无命中时摘要写明"按通用策略执行" | §9 | `context.rs`、`executor.rs` 收敛段 |
| 2 | 超出能力 | 打分无人达标（< 0.45）由 super-agent 自行承接；能力矩阵外直接拒绝并列出可做项 | §2 + §11 | `routing.rs`、`capability.rs` |
| 3 | 幻觉 | 三道防线：来源约束（RAG 引用记忆/文档）→ `agreement_score` 低于阈值降级 → 结果标注证据与置信度（**实现深度见 §12，不夸大**） | §12 | `executor.rs`、`capability.rs` C25 |
| 4 | 合规 | `guard-agent` 复核 + 红线否决（7 条），命中即阻断不放行 | §3 | `executor.rs` `REDLINES` |
| 5 | 循环报错 | 单步重试上限 2 次 → 失败步累计 3 熔断；连续拒绝 3 终止，不死循环 | §5 + §6 | `executor.rs` |
| 6 | 安全降级 | 预算不足按 deep→standard→fast 降档，最多 2 次；降无可降 `aborted_budget`。**安全项不降级** | §4 + §11 | `executor.rs` |
| 7 | 交互风格 | 拒绝也要说人话：统一 Problem JSON + `details` 指字段 + 中文 message，不甩裸堆栈 | §1 + `docs/04` §1/§3 | `error.rs` |

## 1. 三道闸门的位置

```text
请求进入 ──(闸门一：入口治理)── 鉴权 / 体积 / 配额
   │
   ├─ 每步执行前 ──(闸门二：步内治理)── RBAC → 红线 → 预算 → 执行 → 失败重试/熔断
   │
   └─ 收敛前 ──(闸门三：出口治理)── 终态定级 + 置信度结算 + 审计记账
```

闸门二是核心：**一次越权不该让整个任务崩，但连续三次越权必须崩**——
前者是"这一步不行"，后者是"这个 agent 在图谋不轨"。两者的处置刻意不同。

## 2. 权限边界

七项**原子权限**（`src/security/rbac.rs`）：

| 权限 | 授予的能力 |
| --- | --- |
| `Read` | 读取上下文、文件、记忆 |
| `Write` | 写入产物 |
| `SandboxExec` | 在沙箱内执行外部进程 |
| `MemoryWriteShared` | 写共享作用域记忆 |
| `MemoryWriteSystem` | 写系统作用域记忆（最高敏感） |
| `CrossAgent` | 跨 agent 调用/委派 |
| `Admin` | 观测台、审计、组件管理 |

三档权限组（`ORCH_TRUSTED` / `WORKER` / `READONLY`）分别绑给编排型、执行型、只读型 agent，
逐 agent 的实际权限见 `docs/03`（该文件由源码生成，改源码不改文档会当场红）。

三条硬规则：

1. **权限不能临时提权**。任务中途不存在"这次特殊放行"的通道。
2. **越权不是失败**。越权步骤记为 `authz-denied`，不执行、不计入失败重试；连续 `3` 次越权
   （`MAX_DENIED_STREAK`）→ `AbortKind::Permission`，任务终止。指标 `sa_authz_denied_total`。
3. **写系统记忆需要专门权限**。普通 agent 只能写 `private` / `shared`。

## 3. 红线：命中即阻断

`src/orchestration/executor.rs` 的 `REDLINES` 共 **7 条**，覆盖四类风险：

| 类别 | 覆盖的意图 | 处置 |
| --- | --- | --- |
| 凭据泄露 | 明文口令、密钥类索取 | 阻断，任务不执行 |
| 个人信息 | 身份证号、银行卡号等敏感标识索取 | 阻断 |
| 违法操作 | 窃取、盗取类意图 | 阻断 |
| 越权访问 | 绕过登录、未经授权访问 | 阻断 |

设计取舍：**红线不走降级通道**。预算超了可以换小模型省着跑，红线命中了没有"降一档试试"这一说——
一旦允许降级，就是给越权留了后门。

## 4. 预算边界

| 项 | 值 | 来源 |
| --- | --- | --- |
| 默认预算 | 60,000 tokens | `SA_TASK_BUDGET_TOKENS` |
| 降档次数上限 | 2 次 | `executor.rs` |
| 单次降档后步预算 | 原 `est × 0.4` | 同上 |
| 降无可降 | `AbortKind::Budget` → 终态 `aborted_budget` | 同上 |

行为链：某步预示要超预算 → 模型档位下调（`deep → standard → fast`）→ 单步预算压到四成 →
仍不够 → **中止，不硬撞**。每次降档打 `sa_budget_downgrades_total`，trace 里有一条
`outcome: "downgrade"` 的步骤记录——事后能回答"这次为什么变慢了/变糙了"。

## 5. 熔断与中止

| 触发 | 判据 | `AbortKind` | 终态 | 指标 |
| --- | --- | --- | --- | --- |
| 失败步累积 | `failed_steps ≥ 3`（`MAX_FAILED_STEPS`） | `Circuit` | `failed` | 失败步计数 |
| 连续越权 | `denied_streak ≥ 3` | `Permission` | `failed` | `sa_authz_denied_total` |
| 预算耗尽 | 降档后仍超 | `Budget` | `aborted_budget` | `sa_budget_downgrades_total` |
| 用户取消 | `POST /tasks/{id}/cancel` | `Cancel` | `cancelled` | 不计失败 |

**中止要"干净"**：中止只发生在步骤边界，不会打断正在写的文件；已完成的步骤结果保留在 trace 里，
终态与 `result_summary` 明确写出"因何中止"，不做成功伪装。

## 6. 重试边界

- 重试上限 `SA_TASK_RETRY_LIMIT`（默认 2），即**最多尝试 3 次**（首次 + 2 次重试）。
- 退避按指数：`backoff_ms × 2^(attempts-1)`；本地默认 `backoff_ms = 0`（不退避，测试友好），
  对外部进程 runner 可调大。
- **重试不产生新步骤**，仍记在原步上（`attempts` 递增），避免"重试把时间轴撑爆"。
- 越权、红线命中**不重试**。重试只针对"可重试的失败"（超时、进程非零退出等）。

## 7. 限流与体量边界

| 面 | 限额 | 配置 |
| --- | --- | --- |
| 提交任务 | 60 次/小时/用户 | `SA_TASK_SUBMIT_QUOTA_PER_HOUR` |
| 注册 | 10 次/小时/IP | `src/services/auth.rs` |
| 登录 | 10 次/分钟 | 同上 |
| 刷新令牌 | 30 次/分钟 | 同上 |
| 请求体 | 256 KB | `SA_MAX_BODY_BYTES` |
| 异步并发 | 8 个在跑 | `SA_ASYNC_MAX_RUNNING` |
| 单步执行超时 | 20 s | `SA_RUNNER_TIMEOUT_SECS` |
| 脚本进程内存上限 | 2048 MB | `SA_RUNNER_MEM_MB` |
| 脚本并发子进程 | 8 个 | `SA_RUNNER_MAX_PROCS` |
| 审计缓冲 | 2,000 条 | `SA_AUDIT_CAPACITY` |

限流是令牌桶：按 key 独立计桶，超限回 `429` + `Retry-After`，且**不计入审计拒绝**
（配额打满不是安全事件，不应该污染审计口径）。

## 8. 沙箱边界

每个 agent 在花名册里带一个沙箱画像（只读 / 仓库可写 / 文档可写 / 网络只读 / 禁执行等组合），
实际取值由 agent 定义决定，明细见 `docs/03`。

必须说清的限制：**资源有上限，身份与网络仍然没有隔离**。`process` runner 能限制工作目录、
超时、参数画像；Windows 下每个脚本进程 spawn 后立即挂进 Job Object（`runners/sandbox.rs`），
内存与并发进程数由内核兜底——超限时是脚本自己失败，不会拖着整机换页；后端退出时句柄关闭
连带收掉整棵进程树，不留孤儿。挂不上会打 warn 并如实标注"本步无沙箱"，不冒充受控。

仍做不到的三件事，不粉饰：**没有降权账户**（脚本仍以当前用户身份跑）、**没有网络隔离**、
**没有文件系统隔离**。补这两项要换 `CreateProcessAsUser` / AppContainer + WFP 规则
（Linux 侧对应 cgroup v2），属换件范畴——业务层与治理层一行不改。

## 9. 输入边界的兜底

| 情况 | 处置 |
| --- | --- |
| 路由打分低于门槛 `0.45` | 不瞎猜，交由 `super-agent` 自行承接（它有权动态拆步） |
| 目标无法拆成步骤 | 任务直接 `failed`，`result_summary` 写明"无法拆解，原因..."，**不假装成功** |
| 空目标 / 超长目标 | 入口 422，`details` 指到 `goal` 字段 |
| 不存在的 `task_type` 等枚举 | 422，不静默回退默认值（静默回退会让前端以为提交成功） |
| `task_id` 不存在 | 404，且不泄漏"是否存在过"的额外信息 |

## 10. 记忆边界

| 作用域 | 谁能读 | 谁能写 |
| --- | --- | --- |
| `private` | 本人 | 本人（含普通 agent 代为写入） |
| `shared` | 被授权的 agent | 需 `MemoryWriteShared` |
| `system` | 全域 | 仅需 `MemoryWriteSystem`（管理员级） |

跨作用域的写入差异是**权限问题而非参数问题**：没有权限时返回 403，不返回"已保存但未生效"。

## 11. 不可配置清单（刻意不提供开关）

以下五项没有"关闭"的环境变量，改它们等于改代码：

1. 七项原子权限与三档权限组
2. 红线表（7 条）
3. 审计落盘与启动自检（写不出审计就拒绝启动，见 `audit-probe-test.py`）
4. 越权/失败熔断阈值（`3 / 3` 为编译期常量）
5. 终态枚举与中止语义

理由：这些是"安全属性"而非"运维参数"。把它们做成开关，等于把"能不能被绕过"交给环境变量。
