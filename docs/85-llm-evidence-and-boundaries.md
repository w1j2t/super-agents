## 2. JSON 模式到底贡献了多少（老实说：本文只能给方向）

2B 模型不开 JSON 模式时，会把 JSON 包进 `"""` 再跟一段中文解说，`json.loads` 全失败，
于是静默回退规则骨架——**看起来一切正常**。

| 配置 | 样本 | 模型轮平均耗时 | 采纳 |
| --- | --- | --- | --- |
| 关（`SA_LLM_JSON_MODE=0`） | 3 轮 | 41.2 s（31.5 ~ 60.2） | 3/3 |
| 开（`SA_LLM_JSON_MODE=1`） | 20 轮 | 31.9 s（17.7 ~ 45.5） | 20/20 |

差值约 **-23%**。但必须说明：两次样本量不对称（3 轮 vs 20 轮）、且不在同一时间窗，
模型是否常驻内存会影响单轮耗时（`docs/81` §4 记录过 111.9 s → 102.6 s 的常驻效应）。
因此上表只作**方向性证据**：开 JSON 模式更快、更稳，但"快多少"不作为承诺。
早前注释里"快 2.8 倍"的说法产自另一组对比，**本文不沿用**——找不到那份原始数据就不该继续引用它。

| 现象 | 触发条件 | 处置 |

## 4. 边界一：告警只做识别与通知，不自动处置

能力声明写的是"自动处置限于停止重试与降档，不做数据删除"。本项目里这两件事**已经各自有归属**：

| 声明里的"自动处置" | 既有归属 | 可验证指标 |
| --- | --- | --- |
| 停止重试 | 执行器熔断器 | `sa_task_circuit_open_total` |
| 降档 | 预算超支时的模型档位降档 | `sa_budget_downgrades_total` |
| 数据删除 | **不做**（任何情况下） | — |

告警系统再实现一遍，就会出现"两个地方都在决定要不要重试"——这是经典事故源。
因此 `src/obs/alert.rs` 只有 `evaluate` 一个入口：判定 → 去重 → 聚合 → 打点在同一个临界区里
一次完成，并在 `auto_action` 字段如实报出"此刻是哪一个既有机制在兜底"。

**这是边界，不是缺口。** 判据在门禁 19（`scripts/probe_alerting.py`，36 条断言）。

## 5. 边界二：压测撞限流，红的是探针不是系统

`soak-v1`（110 轮）在第 83 轮之后 G1/G4/G5 全线转红，一度被读成"agent 质量退化"。真实原因：

- `POST /tasks` 的提交配额是**每用户每小时 60 次**（`SA_TASK_SUBMIT_QUOTA_PER_HOUR`，默认 60）；
- 那次压测跑在**单账号**上，83 轮之后所有提交都是 `429 提交过于频繁`；
- 被拒的是"提交"这个动作，不是 agent 的产出——那 40 轮模型轮反而全部 G3 通过。

修法不是提高配额（那会把风控改成摆设），而是让探针按用户轮转：

| 改动 | 做法 | 效果 |
| --- | --- | --- |
| 多账号轮转 | `--users N`（默认 3），每轮 `set_active` 切换到下一个账号，令牌 30 分钟自动续期 | 100 轮 / 8 账号 ≈ 每账号 13 次，远离 60 的线 |
| 限流单独断言 | 新增 G8：独立账号连打，**必须**在第 61 次拿到 429 且带 `Retry-After` | 轮转让"限流没被测"，G8 把它补回来；两者缺一即造假 |
| 节流观测 | 行记录里加 `throttled` / `waited_s` / `user` | 一眼看出某轮是否被限流挡过，不用猜 |

一句话：**轮转负责跑得完，G8 负责限流没被绕过。** 只做轮转会让限流失去证据，只做 G8 长跑跑不完。

### 5.1 100 轮实测（2026-11-14 08:11）

| 判据 | 结果 |
| --- | --- |
| G1 正常轮 succeeded | **80/80** |
| G2 模型轮 tokens>0 | 20/20 |
| G3 模型产出**被采用** | **20/20** |
| G4 快轮路由与形状 | 60/60 |
| G5 坏输入被拒 | 20/20 |
| G6 5xx | 0 |
| G7 台账 vs 建单 | 80 : 80（8 账号各 10 条） |
| G8 限流 | 第 61 次 429，`Retry-After=60`；前 60 次无提前 429 |

耗时：模型轮 44.4 s 均（29.9 ~ 60.5），快轮 5.74 s 均（含 4 个垂直域的真实执行）；
`throttled_rounds=0`、`throttle_wait_s=0` —— 轮转设计生效，一次都没被限流挡住。

**最值得看的一行**是路由命中：`game-agent 4 / finance-agent 4 / legal-agent 4 / data-agent 4`。
四个垂直 agent 不是"注册表里躺着"，而是在 100 轮里各自真的被投到了 4 次——这比"花名册有 12 个"
有意义得多。要证明一个新 agent 不是纸面功能，最硬的证据就是它在长跑里被路由、被执行、被采用。
