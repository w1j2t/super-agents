# 运维手册（code-agent 的运行态排障底座）

> 归属说明：本手册原先挂在一个只登记 `Coding` 的独立运维 agent 上，与 `code-agent`
> 的任务类型组合完全重合，按立册条件 A1 不合格，该 agent 已裁撤。手册保留，改由
> `code-agent` 引用——代码跑起来之后的问题，本来就属于同一个域。

用途：`runbook` / `incident-triage` / `change-plan` 技能的执行判据。
原则：**先止损，再定位，最后修根因**。顺序反了，往往在定位过程中把小事故放大成大事故。

---

## 1. 事故分级

| 级别 | 判据 | 响应 |
| --- | --- | --- |
| P0 | 全量不可用 / 数据损坏风险 | 立即止血，5 分钟内要有对外口径 |
| P1 | 核心功能不可用或错误率 > 10% | 15 分钟内止血 |
| P2 | 部分用户受影响 / 性能明显劣化 | 1 小时内处理，可排期 |
| P3 | 轻微异常，有绕行方案 | 当班处理即可 |

判定不看"感觉严重"，看**影响面 × 是否在恶化**。

## 2. 止血三首选（按代价从小到大）

1. **回滚**：最近一次变更能撤就先撤。撤之前确认"撤了会不会更糟"。
2. **降级**：关掉非核心功能、切只读、限流、排队。先保住主链路。
3. **扩容/切换**：加副本、切备用实例、切换上游。

**禁止**：事故进行中直接改代码上线（除非回滚不可行且已验证）。

## 3. 定位顺序（先便宜后昂贵）

```
1 最近变更（配置/发布/依赖/证书/定时任务）—— 80% 的事故在这里
2 资源面（磁盘满、内存、连接数、句柄、句柄泄漏、端口占用）
3 依赖面（上游超时、DNS、证书过期、限流）
4 流量面（突增、重放、爬虫、异常来源）
5 应用面（错误日志、慢查询、锁等待、内存泄漏）
```

每一步都要**写下你排除了什么、依据是什么**。这份排除记录比结论更有价值。

## 4. 必备观测项（没有这些就别谈定位）

- 指标：请求量、错误率、P95/P99 延迟、资源水位、连接池占用。
- 日志：结构化、含 trace_id、打全"对象+操作+原因"。
- 告警：有阈值且有抑制规则（避免一次故障打 200 条）。
- 变更记录：谁、何时、改了什么、能否回滚。**没有变更记录，定位时间至少翻倍**。

## 5. 变更计划（change-plan）必填

| 项 | 内容 |
| --- | --- |
| 变更内容 | 一句话，可读给非技术人员听 |
| 影响面 | 哪些接口/用户/时段 |
| 前置检查 | 备份、容量、依赖可用性 |
| 回滚方案 | 具体命令 + 回滚耗时 + 回滚后需验证什么 |
| 验证方式 | 变更后 3 分钟内能看到的信号 |
| 窗口 | 具体时段，避开高峰 |
| 值守 | 谁盯、盯多久 |

缺"回滚方案"的变更计划，一律打回。

## 6. 复盘（blameless）

结构：**时间线（精确到分钟）→ 影响 → 直接原因 → 根本原因 → 为什么没被早点发现 → 改进行动（人/事/期限）**。

- 只说系统与流程问题，不追个人责任（追责的结果是下次没人敢报）。
- 根本原因至少追问三层"为什么"，但避免无限递归到"人类本质"。
- 每条改进行动必须可验证（比如"补一条磁盘水位告警 + 演练一次"），不能是"加强意识"。

## 7. 常用检查命令（Windows 环境）

```powershell
# 端口占用
Get-NetTCPConnection -LocalPort 8080 -State Listen | Select-Object OwningProcess
# 进程资源
Get-Process | Sort-Object CPU -Descending | Select-Object -First 10 Name,CPU,WS
# 磁盘
Get-PSDrive -PSProvider FileSystem
# 最近修改的文件（定位"刚刚改了什么"）
Get-ChildItem -Recurse | Where-Object LastWriteTime -gt (Get-Date).AddHours(-2)
```

## 8. 红线

- 不在生产直接改代码；改配置也要留旧值。
- 不删日志、不清数据来"让告警消失"。
- 不隐瞒事故。对外口径可以缓，但不能假。
- 任何"重启试试"之前，先确认重启会丢失什么（内存态、未落盘数据、长任务进度）。
