# 测试与验收策略（qa-test-strategy）

> 用途：`qa-agent` 的 `doc_refs` 目标文件。
> 一条硬规矩：**没有复现步骤（前置条件 / 操作 / 预期）的不是缺陷，是抱怨。**
> 代码实现归 `code-agent`，本文只管"怎么判定它做对了"。

## 1. 模糊验收词 → 可测指标

验收会上的争吵八成来自这些词。开会前必须换掉：

| 模糊词 | 换成什么 | 判定门槛示例 |
| --- | --- | --- |
| 流畅 | 帧率与掉帧 | P1 帧率 ≥ 55、掉帧率 < 1%、单次卡顿 > 100ms 的次数为 0 |
| 稳定 | 崩溃率与错误率 | 崩溃 < 0.1%/会话、无数据丢失级错误、连续 8 小时不劣化 |
| 快 | 时延分位 | P95 < 300ms、P99 < 800ms、首屏 4G 下 < 1.5s |
| 好用 | 任务成功率 | 首次使用者完成核心任务成功率 ≥ 80%，平均步数 ≤ 5 |
| 好看 | 视觉走查 | 按设计稿逐项：间距 / 字号 / 色值 / 图标对齐，偏差项为 0 |
| 兼容 | 机型覆盖 | Top 20 机型 + 最低配置机，每台跑通核心路径 |
| 安全 | 越权用例 | 越权 / 注入 / 重放三类全部拒绝，且拒绝留审计记录 |
| 差不多 | 容差 | 写清允许偏差（如 ±5%），否则无法判定 |

**只报准确率不报拒答率的"智能"，一律视为刷分。**

## 2. 用例三张表

只测"正常走一遍"是最常见的漏测来源。三张表都要有：

**① 等价类**：有效类各取一个代表，无效类逐个验证并给出明确报错（不能静默失败）。

**② 边界值**：下边界（0/1/空串/空列表）、上边界（最大值、最大长度、刚好超一位）、
越界（负数、超长、超深嵌套）、特殊值（空白、全角、emoji、换行、零宽字符）。

**③ 异常路径**：网络（断网/弱网/超时/乱序）、并发（重复提交、并发写同一资源、中途取消）、
权限（未登录、无权限、权限中途收回）、外部依赖（下游 5xx、变慢、返回格式变了）、
中途退出（提交中断、刷新、进程被杀后状态是否可恢复）。

## 3. 缺陷分级（给门槛，不给形容词）

| 级别 | 判定门槛 | 处置 |
| --- | --- | --- |
| 阻塞 | 主流程走不通 / 数据丢失或错乱 / 崩溃且稳定复现 | 当版必修，不得延期 |
| 严重 | 核心功能结果错误但可绕过；或仅特定条件触发 | 当版修；有可行绕行可评估延期 |
| 一般 | 非核心功能错误、文案错误、异常提示缺失 | 排入下个迭代 |
| 轻微 | 视觉偏差、体验瑕疵，不影响任务完成 | 随版本顺手修 |

分级争议的根因通常是"是否影响用户完成任务"没有先说清，而不是标准不够细。

## 4. 回归范围裁剪

不做全量（跑不完），也不裸奔（靠运气）。按**改动点**决定必测项：

| 改动 | 必测 |
| --- | --- |
| 数据模型 | 读写迁移、旧数据兼容、回滚路径 |
| 接口契约 | 调用方全量回归、错误码变化、字段可空性 |
| 权限逻辑 | 越权用例、匿名访问、权限变更后的会话失效 |
| 并发/异步 | 重复提交、超时重试、任务取消、乱序响应 |
| 计费/额度 | 边界额度、并发扣减、退款或补回、对账一致性 |
| 纯文案/样式 | 目标页面走查 + 关键流程冒烟，不必全量 |

## 5. 交付要求

每条用例必须写明：前置条件 / 操作步骤 / 预期结果 / 判定门槛。
缺任意一项，用例不可执行，不能计入覆盖率。
