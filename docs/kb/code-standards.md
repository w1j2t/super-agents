# 代码规范（code-agent 领域底座）

语言以 Rust 为主（后端），Python 用于脚本与 worker。规则只写"能被检查出来的"和"踩过坑的"，不写空洞口号。

---

## 1. Rust

### 所有权与生命周期
- 优先借用（`&T` / `&str`），需要持有才 `clone`；`clone` 出现三次以上先找结构问题。
- 函数入参用 `&str` 而非 `&String`，用 `&[T]` 而非 `&Vec<T>`。
- 结构体里存 `String` 而不是 `&'a str`，除非确有零拷贝需求且能说清生命周期来源。
- 返回迭代器优于返回 `Vec`，但也别为了"零分配"把签名复杂到没人看得懂。

### 错误处理
- 库层用 `thiserror` 定义错误枚举，应用层用 `anyhow`。
- **禁止 `unwrap()` / `expect()` 出现在请求处理路径**（测试、启动期初始化可以用，但 `expect` 要写清前提）。
- 错误信息必须包含"什么对象 + 什么操作 + 为什么失败"三要素，例如 `打开存储文件失败：path=... err=...`。
- 不要用 `?` 把错误吞成 `500`：能归类成 4xx 的必须归类（参数错 422、未授权 401、越权 403、不存在 404）。

### 并发
- 共享状态用 `Arc<...>`，可变共享用 `Mutex` / `RwLock`；**持锁不做 IO**，尤其不做网络与磁盘写。
- 需要跨步骤并行的，用 `std::thread::scope` 借用只读快照，避免为了并行给全部数据 `clone`。
- 不引入 async 与 sync 混用；同一层里只出现一种。

### 命名与结构
- 模块按"域"划分，不按"技术层"划分（`domain/agent.rs` 优于 `models/agent_model.rs`）。
- 公开 API 必须写文档注释，说明**契约**（输入范围、返回含义、失败条件），而不是复述函数名。
- 魔法数字必须提成常量并写清来历（阈值来自哪里、改了会影响什么）。

## 2. Python（脚本与 worker）

- 只用标准库（脚本要能在干净环境跑），第三方依赖要显式声明并给出安装命令。
- 脚本统一：`main()` 返回退出码，`0` 通过 / `1` 断言失败 / `2` 脚本自身配置错 / `3` 环境不具备（SKIP）。
- 遍历/断言空集合要堵：`all([])` 恒真，必须配 `len(...) > 0`。
- 文件读写显式指定 `encoding="utf-8"`；Windows 写文本注意换行（`newline=""` 或统一 `\n`），否则整文件 diff 噪声。

## 3. SQL

- 索引：WHERE / JOIN / ORDER BY 用到的列优先；联合索引注意最左前缀。
- 禁止 `SELECT *` 进生产代码；查询必须显式列名（也防止加列后反序列化炸掉）。
- 分页用游标（keyset）而非深 `OFFSET`；`OFFSET 100000` 的代价接近全表扫。
- 写操作必须能回答："失败了怎么回滚 / 重放会怎样"。

## 4. 提交与变更

- 一次提交只做一件事；重构与改行为不要混在一起。
- 改行为必须同时给出：改了什么、为什么、怎么验证（命令/测试名）。
- 没有版本控制时：**改之前先备份副本**，不要靠"我记得原来是什么"回退。

## 5. 自检清单（提交前）

- [ ] 编译通过，clippy 无新增警告
- [ ] 新增逻辑有对应测试，且测试**曾在修复前失败过**（否则不知道它测的是什么）
- [ ] 错误路径有覆盖（非法输入、超时、外部失败）
- [ ] 无 `unwrap()` 落在请求处理路径
- [ ] 日志不含敏感字段（密码、token、完整身份证/银行卡）
- [ ] 公共 API 文档注释已更新
