# 中文写作风格（doc-agent 领域底座）

面向中文书面语：报告、周报、方案、公文、商务邮件、会议纪要。目标是**读者一眼能拿到结论，回头能查到依据**。

---

## 1. 三条底线

1. **结论先行**：第一段就给出结果或判断，不要"随着……的不断发展"开场。
2. **一段一事**：一段只讲一个意思，超过 5 行考虑拆段。
3. **有据不夸张**：不写"极大提升""显著优化"这类无刻度词；要么给数，要么写清判断依据。

## 2. 结构与篇幅

| 文体 | 骨架 | 目标篇幅 |
| --- | --- | --- |
| 周报 | 本周完成 → 遇到的阻塞 → 下周计划 → 需要的支持 | 300~600 字 |
| 方案 | 结论/推荐 → 背景 → 方案对比 → 取舍理由 → 风险 → 落地步骤 | 800~2000 字 |
| 汇报 | 结论 → 关键数据 → 原因 → 下一步 | 400~800 字 |
| 公文/通知 | 事由 → 具体安排（时间/地点/责任人） → 要求 | 200~500 字 |
| 商务邮件 | 一句话目的 → 需要对方做什么 → 期限 → 附件说明 | 120~250 字 |
| 会议纪要 | 决议 → 待办（人/事/期限） → 待定事项 → 分歧记录 | 200~500 字 |

## 3. 用词规范

- **禁用空壳词**：赋能、抓手、闭环（除非本义）、打通、沉淀（当"记录"讲时）、生态位（当"位置"讲时）。
- **量化优先**：把"大幅下降"改成"从 12.4% 降至 7.1%（-5.3pp）"。
- **单位与精度统一**：百分比与百分点分清；金额写清币种与含税口径。
- **人称**：正式文档用"本部门/我方"，避免"我们觉得"；对内沟通可用"我们"。
- **术语一致**：同一概念全文一个叫法，首次出现给定义或指向术语表。

## 4. 常见毛病（自检）

- [ ] 开头三段还没进入正题
- [ ] 段落之间靠"此外""同时""另外"串联（说明逻辑关系没想清）
- [ ] 出现无法验证的最高级（最、唯一、完全、彻底）
- [ ] 数据没有来源与时间
- [ ] 待办没有责任人与期限
- [ ] 结论里混着过程叙述（把"我查了 A、B、C"当结论）

## 5. 商务邮件细则

- 主题：`【动作】对象 - 期限`，例如`【请确认】Q4 预算表 - 11/20 前`。
- 一件事一封邮件；需要多件事时就列编号清单，不要埋在第 3 段里。
- 收件人顺序：主送（办事的人）→ 抄送（需要知情的人），不要用抄送施压。
- 结尾只写需要对方做什么，不写"如有问题随时沟通"这类无动作的客套。

## 6. 会议纪要细则

```
时间/地点/参会人/缺席人
一、决议（已定的事，含决议依据）
二、待办（负责人 | 事项 | 期限）
三、待定（悬而未决 + 卡在谁那里 + 下次讨论时间）
四、分歧记录（谁持不同意见、理由，不改写成"一致通过"）
```

红线：**没形成决议的写成"待定"，不要把讨论过程写成结论**。

## 7. 交付前最后一遍

- 通读只看第一段和每段首句，能不能读懂全文骨架？不能就重排。
- 所有数字回头核一次来源（尤其是自己算的合计）。
- 所有"待确认"都显式标出来，不要用模糊表述掩盖未定事项。
