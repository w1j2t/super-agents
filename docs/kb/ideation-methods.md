# 创意方法（ideation-agent 领域底座）

用途：`concept-diverge` / `idea-scoring` 技能的执行判据。
原则：**先求量再求质**（发散阶段禁止评价），**收敛阶段用统一尺子**。混在一起的头脑风暴产出，质量必然取决于嗓门最大的人。

---

## 1. 发散四法

### 1.1 SCAMPER（改造已有对象）
对现有方案逐项问：替代 / 组合 / 调整 / 修改 / 另作他用 / 消除 / 重排。
适合：改进型需求（"现有流程怎么更快"）。

### 1.2 强制关联（Random Pairing）
抽两个不相关词，强行搭桥。例：技能树 × 菜谱 → "配方即天赋：收集材料解锁组合技能"。
适合：卡壳时破局，产出多为半成品，需要二次加工。

### 1.3 极端化（Premise Removal）
拿掉一条默认前提，看世界怎么变。例："如果没有等级" → 纯装备驱动；"如果玩家只能操作一次" → 一击定胜负的动作游戏。
适合：找品类创新点。

### 1.4 逆向（Inversion）
把目标反过来说。例："怎么让用户更快流失" → 答案取反就是留人清单。
适合：快速找出被忽略的负面因素。

## 2. 发散阶段纪律

- 时长限定 8~12 分钟，产出目标 10~20 条，**不许中途否定任何一条**。
- 每条只写一行：`一句话机制 + 它改变了玩家的什么体验`。
- 不允许"更好""优化""提升体验"这类没有机制的表述。
- 记录原话，不急着润色（润色会提前杀掉粗糙但好的想法）。

## 3. 收敛：四维打分

| 维度 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 差异化 | 市面上到处都是 | 有小创新 | 明显不同且能说清不同在哪 |
| 可落地 | 需要重做底层 | 有技术难点但路径清楚 | 现有能力可直接做 |
| 体验收益 | 玩家感觉不到 | 部分玩家能感知 | 核心体验直接变好 |
| 风险 | 高风险/合规问题 | 有中等风险 | 风险可控且有兜底 |

**排序规则**：先按"可落地 + 体验收益"求和排序，再看差异化。差异化高但不可落地的概念，放"未来储备"，不占当前资源。

## 4. 概念卡格式

```
【概念名】一句话（≤20 字）
【核心机制】玩家实际做什么（一段操作描述，不是形容词）
【改变了什么体验】原来 → 现在
【为什么有趣】说出一个"啊哈"点
【实现成本】低/中/高 + 主要难点在哪
【风险】最可能死在哪
【验证方式】最小可行测试怎么做（1 天内能验证）
```

## 5. 常见失败模式

1. **形容词驱动**：全是"更沉浸""更爽"，没有机制，无法实现也无法评估。
2. **缝合怪**：A 的循环 + B 的美术 + C 的付费，但没说清为什么它们放一起会更好。
3. **只发散不收敛**：出 50 条谁都不许否，最后等于零。
4. **过早优化**：第一轮就开始讨论性能与成本，杀死所有新想法。
5. **无验证路径**：概念很好，但没人知道怎么花一天验证它是不是真的。

## 6. 交付格式

1. 简明列出 10~20 条原始概念（一行一条，保留粗糙感）。
2. 四维打分表（含理由一列，只写一句）。
3. Top 3 概念卡（完整格式）。
4. 推荐 1 条 + 推荐理由 + **最小验证方案**（一天内能做什么）。
5. 储备清单（差异化高但当前不可落的，写清等什么条件成熟再做）。
