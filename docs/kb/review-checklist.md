# 代码评审清单（code-agent / review-checklist）

用途：`code-review` 技能的执行判据。评审**先看结论再看细节**，绝不从第一行读到最后一行。

---

## 0. 评审顺序（五遍法）

1. **意图**：这个改动想解决什么问题？如果描述里没有"为什么"，先问，别猜。
2. **边界**：正常路径之外，非法输入、空值、超大输入、并发、失败重试会怎样？
3. **契约**：对外形状变了吗？（接口字段、错误码、状态机、事件格式）变了必须同步调用方与文档。
4. **资源**：持锁 IO、无界队列、未关闭句柄、内存随请求增长。
5. **可读性**：命名是否说了"是什么"而非"怎么做"；注释是否解释了"为什么"。

## 1. 阻断级（必须改，否则不予通过）

- [ ] 请求路径上的 `unwrap()` / `expect()` / `panic!`
- [ ] 未校验的外部输入直接进查询或路径拼接（注入风险）
- [ ] 敏感信息落日志或进错误信息（密码、token、密钥、完整证件号）
- [ ] 权限检查缺失或可被参数绕过
- [ ] 对外形状在不告知的情况下改变（字段删除/改名/类型变化）
- [ ] 破坏性操作无确认、无备份、无回收路径
- [ ] 并发下共享可变状态无保护

## 2. 严重级（应改，需给出理由才可放行）

- [ ] 错误被吞（`let _ = ...` / `#[allow]` 掩盖）导致失败无声
- [ ] 重试逻辑无退避、无上限（打爆下游）
- [ ] 超时缺失：外部调用、锁等待、IO
- [ ] 资源泄漏：临时文件、句柄、订阅未释放
- [ ] 状态机出现不可达状态或非法跃迁未拒绝
- [ ] 测试只测了快乐路径

## 3. 建议级（可后续）

- [ ] 重复代码可抽公共函数（三处以上才抽，两处别急）
- [ ] 命名与域语言不一致（同一个概念两个叫法）
- [ ] 注释复述代码（`// 设置为 5` 这类）应删除或改写成"为什么是 5"
- [ ] 魔法数字未提常量

## 4. 评审输出格式

```
【结论】阻断 N 项 / 严重 M 项 / 建议 K 项 → 不建议合并 / 改后可合并 / 可合并并跟进
【阻断项】文件:行 — 问题 — 后果 — 建议改法
【严重项】…
【建议项】…
【我没看懂的地方】…（明确列出，不假装理解）
【未覆盖的验证】需要补哪个测试/哪次手动验证
```

## 5. 评审纪律

- 只评审改动及其影响面，不顺手要求重构无关代码。
- 结论必须**落到文件与行**，不说"整体感觉不太好"。
- 论断要给出依据：语言语义、文档规则、实测行为。**不臆造标准编号或官方说法**。
- 拿不准的地方写进"我没看懂的地方"，这比装懂有价值得多。
