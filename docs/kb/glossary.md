# 术语表（doc-agent / glossary）

规则：**同一概念一个叫法**。新增术语先进本表，再在正文使用。表中"禁用写法"一列，出现即视为不一致。

---

## 1. 本系统（personal-super-agents）核心术语

| 术语 | 定义 | 禁用写法 |
| --- | --- | --- |
| super-agent | 唯一入口 agent，负责理解、拆步、选人、收敛 | 总控、大脑、主 agent |
| 子 agent / worker | 承接单域任务的 agent（如 code-agent） | 分身、子智能体、下属 |
| 任务（task） | 一次从 goal 到终态的完整执行单元 | 作业、工单 |
| 步骤（step） | 任务计划中的一次 agent 调用 | 环节、子任务（易与"子任务"混淆） |
| 计划（plan） | 由若干 step 组成的依赖图 | 流程、编排（编排指执行动作） |
| 计划层（layer） | 依赖图中可并行执行的一组 step | 批次、阶段 |
| 路由（routing） | 由 goal 判定 task_type 与承接 agent | 分派、分发（派发专指 dispatch 打分后选定） |
| 派发（dispatch） | 按打分与门槛选定某个 agent 承接 | 分配、指派 |
| 能力（capability） | `capability.rs` 中登记的一项对外承诺 | 特性、功能点 |
| 门禁（gate） | 可自动执行、有明确退出码的验收脚本 | 检查项、测试用例 |
| 负向演练（drill） | 验证门禁自身会失败的演练，不计数入门禁 | 反测试、自测 |
| 槽位（slot） | 可插拔部件挂载点（存储/执行器/审计/限流/指标） | 插槽、接口点 |
| 证据（evidence） | 门禁运行产出的原始记录文件 | 报告、日志（日志另有含义） |

## 2. 机器与运行态

| 术语 | 含义 | 注意 |
| --- | --- | --- |
| 源码区 | 中文路径下的工作区（以它为准） | 不要与"镜像"混用 |
| 编译镜像 | 纯 ASCII 副本，编译与测试都在这里跑 | 不是发布包 |
| 归档 | 运行数据落盘目录 | 不是备份 |
| 活动部件（active） | 当前运行实例实际装载的实现 | 与"配置"不是一回事 |

## 3. 状态与判定

| 术语 | 含义 |
| --- | --- |
| 全绿 | 门禁全部通过且退出码为 0；缺环境记 SKIP 不算绿 |
| 假绿 | 测了旧产物或漏跑断言导致的"看起来通过" |
| 漂移 | 文档/脚本/清单与源码事实不一致 |
| 断链 | 单据或证据链条中间缺一环 |
| 兜底 | 不是最优但保证不失败的路径 |

## 4. 使用建议

- 写文档时先在表中查一眼，别自己造同义词。
- 中文正文里出现英文术语时，首次出现写成「中文（English）」形式。
- 报错信息里的术语同样受本表约束（用户看到的词与文档必须一致）。
