# 游戏设计检查清单（game-agent 领域底座）

用途：游戏品类、核心循环、数值平衡、关卡节奏、奖励结构类任务的判定依据。
原则：**先定循环，再调数值，最后做节奏**。顺序颠倒的话，数值永远在替糟糕的循环背锅。

---

## 1. 核心循环画布（Core Loop Canvas）

一个循环必须能一句话说完，且四段齐全。缺任何一段，循环就是漏的。

| 段 | 要回答的问题 | 缺失时的典型症状 |
| --- | --- | --- |
| 行动 | 玩家每 10~60 秒在重复做什么操作？ | 玩家在界面里发呆、到处乱点 |
| 反馈 | 行动后多久看到结果？结果是否可比较？ | "打了没感觉"、伤害数字看不出差别 |
| 成长 | 结果如何转化为下一次更强的行动？ | 打完一把毫无变化，重开欲望为零 |
| 消耗 | 成长要付出什么代价（资源/时间/风险）？ | 无限攒资源、选择无代价、没有取舍 |

判定口径：
- **单圈时长**：休闲 30~90 秒，中核 3~10 分钟，硬核 15 分钟以上。写清目标值，别写"适中"。
- **成长可见性**：每一圈至少要有一项**玩家能自己对比出来**的变化（数字、外观、解锁）。
- **消耗必须有牙齿**：消耗若可被轻易规避，成长就不成立，循环退化成"时间换数值"。

## 2. 品类坑位（品类 → 该品类最常塌的地方）

| 品类 | 最典型坑位 |
| --- | --- |
| 成长向 RPG | 前期成长爽、中后期曲线变平；技能树出现"必点"与"永不点"两极 |
| 动作/战斗 | 打击反馈（顿帧、位移、音效）不足，判定窗口与动画不匹配 |
| Roguelike/肉鸽 | 随机性只影响数值不影响策略；单局时长与重开成本失衡 |
| 模拟经营 | 中期进入"挂机等资源"，玩家决策密度骤降 |
| 关卡/闯关 | 难度靠堆数值而非新机制；相邻关卡难度跳变 |
| 修仙/武侠 | 境界体系与战力脱钩，突破变成纯时间门槛 |
| 放置 | 首日反馈过密、次日无新目标，留存断崖 |

## 3. 数值轴与健康区间

每条轴都要写：目标区间、越界后的坏信号、调整手段。**没有区间的数值目标等于没有目标。**

| 轴 | 健康区间（起手参考） | 坏掉的信号 | 常用手段 |
| --- | --- | --- | --- |
| 单次战斗时长 | 15~90 秒（视品类） | 低于 10 秒无决策，高于 3 分钟疲劳 | 调血量、调技能冷却 |
| 玩家 DPS 增长 / 章节 | 每章 1.3~1.8 倍 | 超过 2 倍：旧内容瞬间失效 | 分段给、用机制替代纯数值 |
| 资源产出 / 消耗比 | 稳态时 1.0~1.15 | 长期 >1.3 必然通胀；<0.9 玩家被卡死 | 加回收口、调兑换比 |
| 升级所需时间 | 前期 5~15 分钟，中期 1~3 小时 | 相邻档位差超过 3 倍会掉人 | 用曲线函数而非手填表 |
| 随机掉落保底 | 期望次数 1.5 倍内必得 | 连败无保底 = 玩家归因为"游戏在骗我" | 硬保底 + 软保底叠加 |

**通胀控制三问**（每个经济系统都要过）：
1. 资源产出的**上限**在哪里？（每日/每局/每章）
2. 资源的**回收口**有哪些？（修理、消耗品、税率、升级失败损耗）
3. 兑换比改动后，**存量玩家**的资产会怎么变？会不会一夜贬值？

## 4. 关卡节奏与难度曲线

标准四段式：**教学 → 考验 → 翻转 → 高潮**。

- 教学段：只引入一个新变量，允许失败且失败无惩罚。
- 考验段：复用教学变量，加大压力（数量/速度/组合）。
- 翻转段：引入**反向使用**已学机制，或打破一条玩家已确信的规则。
- 高潮段：同时使用两个以上已学机制，给出明确的"我变强了"的体感。

难度检查：
- **相邻关卡**难度增幅 ≤ 1.5 倍体感（用通关率或平均重试次数衡量，别拍脑袋）。
- 每 3~5 关要有一次**节奏换气**（低压力关、叙事关、探索关）。
- 难度提升优先用**新机制**，其次用**组合**，最后才用**数值**。

## 5. 奖励结构

| 维度 | 两端 | 用错时的后果 |
| --- | --- | --- |
| 即时 / 延迟 | 战斗内即时反馈 vs 章节结算奖励 | 全即时 → 无期待；全延迟 → 无爽感 |
| 确定 / 随机 | 固定掉落 vs 概率掉落 | 全确定 → 无惊喜；全随机 → 无掌控 |
| 通用 / 专属 | 通用货币 vs 角色专属材料 | 全通用 → 选择无差异；全专属 → 资源浪费焦虑 |

结构原则：**主成长线用确定奖励，支线探索用随机奖励**。反过来会让玩家觉得"认真玩不如赌"。

## 6. 系统耦合与技能树

- 每个技能树节点必须能回答："**什么情况下我会点它**"。答不上来的节点就是凑数的。
- 禁止出现"必点路径"（不点就玩不下去）与"永不点"（收益趋零）两类节点。
- 节点之间的**互斥与协同**要显式设计：至少 1 组互斥（取舍）、至少 2 组协同（组合乐趣）。
- 技能树的深度优先于广度：8 个每层有效选择，好过 30 个摆设。

## 7. 设计评审（design-review）过闸清单

交付一份游戏设计稿前，逐条自查：

- [ ] 核心循环四段齐全，单圈时长有明确目标值
- [ ] 品类坑位已逐一对照，并写明本设计如何避开
- [ ] 每条数值轴都有区间与越界信号
- [ ] 经济系统过了通胀三问
- [ ] 难度曲线按教学/考验/翻转/高潮分段，且有换气点
- [ ] 奖励结构明确了"确定在哪、随机在哪"
- [ ] 技能树无必点/无废点，至少有互斥与协同
- [ ] 未确认的数字写"待定稿"，并列出待定的判定条件（不臆造具体数值当结论）

## 8. 常见失败模式

1. **数值先行**：先填数值表再想循环 —— 结果是一堆没有决策的数字。
2. **爽感替代设计**：靠爆炸特效与掉落动画掩盖循环空洞，30 分钟后必被看穿。
3. **难度阶梯断裂**：第 7 关与第 8 关是两个游戏，玩家在断点流失。
4. **奖励通胀**：为了留人不停加奖励，最终所有奖励都不值钱。
5. **机制堆叠不消化**：每个版本加一个新系统，系统之间不互认，玩家认知过载。
6. **只调不测**：改完数值不做单局实测，靠"感觉差不多"上线。
